# Plan 01 - Final TR-E Submission Readiness Audit

<objective>
Audit the Phase 5 manuscript package for TR-E submission readiness without
changing the evidence base. The plan adds one hard-contract manuscript
readiness script, runs the roadmap verification suite, writes a reviewer-style
readiness audit, and produces an author-facing final revision task list. The
final answer must state whether Work2 is claim-ready empirical or only a
conditional diagnostic service-menu optimization manuscript.
</objective>

<scope>
In scope:
- Inspect Phase 5 manuscript files and companion claim-control files.
- Inspect current Phase 10 package status, strict claim guard, source map, and
  prior diagnostic lock material.
- Add a hard-contract manuscript readiness package test.
- Run the Phase 6 verification commands and record concise outputs.
- Write `M6_FINAL_TR_E_READINESS_AUDIT.md`.
- Write `TR_E_WORK2_FINAL_REVISION_TASKS.md`.
- Classify every audit dimension as `Blocker`, `Major`, or `Minor`.

Out of scope:
- Final replay, calibration, checkpoint training, case-study execution, or
  artifact regeneration for claim upgrades.
- Hand-editing generated rows, package status, package indexes, figures,
  tables, mirrors, or claim guards.
- Upgrading any manuscript claim beyond the current strict
  `CLAIM_GUARD.json`.
- Rewriting the full manuscript body during the audit phase, except for the
  dedicated final revision task document.
</scope>

<must_haves>
<truths>
- D-01: Default recommendation is `revise-before-submission` unless the audit supports a stronger judgment.
- D-02: `diagnostic-only but draftable` remains a valid secondary conclusion.
- D-03: `not ready` is reserved for hard failures.
- D-04: The audit report is reviewer-style; the revision task list is author-friendly.
- D-05: The audit uses a two-axis matrix.
- D-06: TR-E contribution risk covers novelty, transportation relevance, model rigor, manuscript structure, and academic writing quality.
- D-07: Evidence compliance risk covers claim safety, source traceability, reproducibility, generated-artifact validity, and strict claim-guard alignment.
- D-08: Axis-level risk informs the final judgment without overriding hard-failure rules.
- D-09: Risk taxonomy is `Blocker`, `Major`, and `Minor`.
- D-10: Every audit dimension receives a taxonomy status.
- D-11: The revision task file uses the requested hybrid template.
- D-12: Submission blockers are true blockers only.
- D-13: Blocker and Major tasks cite evidence or artifact sources.
- D-14: Every revision task has checkable completion criteria.
- D-15: The final checklist includes command checks.
- D-16: Verification covers roadmap commands plus manuscript-focused checks.
- D-17: Add `work2_coding/scripts/test_manuscript_readiness_package.py`.
- D-18: The new readiness script fails only on hard contract breaks.
- D-19: The audit records PASS/FAIL and short output summary for every verification command.
- D-20: Failed manuscript readiness contracts cap or downgrade the final recommendation according to failure severity.
</truths>
</must_haves>

<threat_model>
| Threat | Severity | Mitigation |
| --- | --- | --- |
| Audit accidentally upgrades blocked empirical claims | high | Treat `CLAIM_GUARD.json` as the authority; scan manuscript wording and preserve `claim_ready=false` conclusions |
| Qualitative prose judgment becomes an automated hard failure | medium | Keep `test_manuscript_readiness_package.py` limited to hard file, section, source-path, and claim-safety contracts |
| Source-map paths drift from real files | high | The readiness script checks concrete local source paths where feasible and reports missing paths as hard traceability failures |
| Revision list overwhelms blockers with ordinary improvements | medium | Put only true submission blockers under `Submission Blockers`; route non-blocking issues to Major or Minor revisions |
| Verification output is too verbose to review | low | Record command, PASS/FAIL, and short output summary in the audit, not full logs |
| Generated evidence is edited to make the paper look stronger | high | Do not write under generated evidence roots except by approved test/script creation; do not edit claim guards, package status, rows, figures, or tables |
</threat_model>
