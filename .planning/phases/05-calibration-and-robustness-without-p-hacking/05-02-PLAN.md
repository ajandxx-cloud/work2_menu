# Phase 5 Plan 2: Calibration Manifests And Frozen Final Settings

<objective>
Create or lock the calibration/final manifest contracts and write
`.planning/results/FROZEN_FINAL_SETTINGS.md` so any final rerun is independent,
pre-registered, and gated before it can support stronger manuscript claims.
</objective>

<scope>
## In Scope

- Create calibration and final manifest contracts if needed, using existing
  pilot/formal robust-menu manifests as references.
- Preserve seven-tag policy family, paired replay fairness, checkpoint
  provenance, opt-out/home accounting separation, and normalized-row metadata.
- Add manifest and frozen-settings tests.
- Write `.planning/results/FROZEN_FINAL_SETTINGS.md`.
- Update project planning docs to record whether Phase 5 produced locked
  settings or stopped because gates remain blocked.

## Out Of Scope

- Executing the calibration pilot or final formal rerun.
- Selecting final settings from final test rows.
- Dropping the random baseline, fixed-window ablation, low-uptake splits, or
  unfavorable metrics.
- Upgrading manuscript claims before readiness, artifact status, and claim guard
  pass.
</scope>

<tasks>
## Task 1: Decide Whether New Manifests Are Needed

**Type:** audit
**Files:** `work2_coding/Experiments/studies/pilot_robust_menu.yaml`,
`work2_coding/Experiments/studies/formal_robust_menu.yaml`,
`.planning/results/CALIBRATION_PROTOCOL.md`

**Action:**

1. Compare existing `pilot_robust_menu.yaml` and `formal_robust_menu.yaml`
   against the calibration protocol.
2. If the existing manifests already express the protocol without ambiguity,
   document that no new manifest is needed and make
   `FROZEN_FINAL_SETTINGS.md` cite the existing manifest paths and hashes.
3. If distinct calibration/final contracts are needed, add:
   - `work2_coding/Experiments/studies/calibration_robust_menu.yaml`
   - `work2_coding/Experiments/studies/final_robust_menu.yaml`
4. New manifests must use explicit `tier`, `run_mode`, checkpoint paths,
   output intent, split IDs, policy tags, paired fields, varied fields, and
   normalized-row schema.

**Verify:**

- No manifest names imply that pilot rows are final evidence.
- Calibration and final split IDs/seeds are distinct.

**Acceptance Criteria:**

- `CAL-02` is satisfied either by new manifests or by a written no-new-manifest
  decision backed by hashes.

## Task 2: Preserve Policy And Replay Contracts

**Type:** test
**Files:** `work2_coding/scripts/test_calibration_manifests.py`,
`work2_coding/Experiments/studies/calibration_robust_menu.yaml`,
`work2_coding/Experiments/studies/final_robust_menu.yaml`

**Action:**

Add `scripts/test_calibration_manifests.py` to validate the chosen manifest
contract. The test should accept the implemented path:

- If new manifests exist, validate them.
- If no new manifests exist, validate the documented existing pilot/formal
  paths used by `FROZEN_FINAL_SETTINGS.md`.

Assertions:

1. Both calibration and final contracts include all seven
   `mainline_policy_tags()`.
2. Both require loaded checkpoints and record checkpoint paths.
3. Calibration split IDs/seeds and final split IDs/seeds are disjoint.
4. Paired fields include seed, data seeds, instance, pricing, HGS settings,
   checkpoint path, checkpoint requirement, `menu_k`, `max_candidates`, and
   utility parameters.
5. Varied fields include policy/product/window/pricing/filter/objective and
   opt-out/service guardrail knobs.
6. Output schema includes `checkpoint_load_status`, `checkpoint_hash` if
   supported, `method_family`, `outside_option_util`, opt-out/home/meeting-point
   accounting fields, status fields, and error fields.
7. No policy tag, split, or metric required by the protocol is removed.

**Verify:**

```powershell
cd work2_coding
python scripts/test_calibration_manifests.py
```

**Acceptance Criteria:**

- Manifest drift that would break paired fairness or row provenance fails fast.

## Task 3: Write Frozen Final Settings

**Type:** docs
**Files:** `.planning/results/FROZEN_FINAL_SETTINGS.md`

**Action:**

Write `.planning/results/FROZEN_FINAL_SETTINGS.md` only after the protocol and
manifest contract are settled. Include:

1. Final-setting status:
   - `frozen` if every required item is known and gates allow proceeding;
   - `blocked_pending_gate_cleanup` if readiness/artifact blockers still stop
     final evidence;
   - `conditional_reframe_selected` if the project chooses not to pursue a
     strong final rerun.
2. Final manifest path and SHA-256/hash.
3. Calibration manifest path and SHA-256/hash, if applicable.
4. Seven policy tags.
5. Split IDs/seeds for calibration and final, with proof of separation.
6. Checkpoint path, hash, sidecar path, and load-status requirement.
7. Paired fields and varied fields.
8. Final runtime knobs selected from the protocol, plus rejected alternatives
   and rationale.
9. Commands to run, but not execute in this plan:

```powershell
cd work2_coding
python scripts/train_shared_checkpoint.py --study <final-study> --checkpoint-path <checkpoint-path>
python scripts/check_formal_readiness.py --study <final-study> --output-root outputs/final_readiness
python scripts/run_study.py --study <final-study> --execute --output-root outputs/final_v1
python scripts/build_artifacts.py --run-dir <final-run-dir> --claim-ready --readiness-json outputs/final_readiness/<final-study>/FORMAL_READINESS.json
python scripts/build_manuscript_frame.py --artifact-root <final-artifact-root>
```

10. Abort/downgrade rules after final failure.

**Verify:**

- The document is explicit that it is a pre-run contract, not evidence.
- If blockers remain, it does not say final rerun is authorized.

**Acceptance Criteria:**

- `CAL-03` is satisfied.
