# Phase 5 Plan 1: Gate Cleanup And Calibration Protocol Lock

<objective>
Lock the scientific and procedural boundary for calibration before any new
pilot or final evidence is generated. This plan refreshes blocker visibility
and writes `.planning/results/CALIBRATION_PROTOCOL.md` with explicit allowed
knobs, prohibited tuning behavior, pilot selection rules, and rerun limits.
</objective>

<scope>
## In Scope

- Re-read current formal readiness, artifact status, claim guard, and Phase 4
  diagnosis.
- Refresh or extend `.planning/results/FORMAL_BLOCKER_DIAGNOSIS.md` if current
  gate state differs from the Phase 3/4 diagnosis.
- Write `.planning/results/CALIBRATION_PROTOCOL.md`.
- Add a script-style test that validates the protocol contains required guard
  sections and prohibits p-hacking behaviors.
- Keep dirty-git cleanup as a documented human decision, not an automatic
  executor action.

## Out Of Scope

- Running calibration pilots or final formal reruns.
- Changing algorithm behavior to improve the selected formal ranking.
- Reverting, stashing, deleting, staging, or committing unrelated dirty worktree
  paths without explicit user approval.
- Editing generated normalized rows, generated tables, generated figures, or
  claim guard JSON.
</scope>

## Task 2: Write The Calibration Protocol

**Type:** docs
**Files:** `.planning/results/CALIBRATION_PROTOCOL.md`

**Action:**

Create `.planning/results/CALIBRATION_PROTOCOL.md` with frontmatter and these
sections:

1. Status and source evidence:
   - Phase 4 diagnostic outcome;
   - current readiness/artifact/claim blockers;
   - statement that the selected formal result must not be tuned directly.
2. Allowed calibration knobs:
   - `menu_k`;
   - `max_candidates`;
   - ETA filter mode/threshold;
   - service/opt-out guardrails;
   - uptake regime assumptions;
   - any added knob must include a realism or robustness rationale.
3. Small candidate ranges:
   - roughly 2-3 candidate values per knob where possible;
   - no open-ended search.
4. Prohibited actions:
   - no final-result tuning;
   - no seed/split/baseline/metric deletion;
   - no generated-row/artifact/claim-guard hand edits;
   - no single profit ranking selection.
5. Pilot selection rule:
   - pre-registered multi-metric thresholds;
   - profit non-degradation;
   - acceptance/opt-out/meeting-point uptake signals;
   - service-quality guardrails;
   - regime-specific reporting.
6. Final rerun rule:
   - final settings frozen before run;
   - final run independent from pilot;
   - if final fails, at most one second calibration round with new written
     protocol and mechanism/realism justification.
7. Downgrade rule:
   - after a failed second final rerun, force conditional service-menu framing.

**Verify:**

- Every section maps to at least one of D-01 through D-08 and D-13 through
  D-16 from `05-CONTEXT.md`.
- The protocol says success is process integrity, not a better ranking.

**Acceptance Criteria:**

- `CAL-01` is satisfied.
