# Phase 9 Plan 2: Tractability Artifact Builder And Summary Gate

<objective>
Implement generated Phase 9 tractability artifact and summary tooling. The
tooling must read normalized rows and manifest snapshots, validate the 15-row
exact-greedy contract, build diagnostic artifacts, and write
`.planning/results/COMPUTATIONAL_TRACTABILITY_SUMMARY.md` without upgrading
claims.
</objective>

<scope>
## In Scope

- Add `work2_coding/Src/computational_tractability.py` with loaders,
  validators, aggregators, claim-boundary classification, and Markdown
  generation.
- Add CLI wrappers for Phase 9 generated tractability artifacts and the
  planning-side summary.
- Generate JSON/CSV/LaTeX/figure outputs from normalized rows plus manifest
  snapshots.
- Preserve `claim_ready=false` and explicit blocker reasons from upstream
  status gates.
- Add tests using synthetic normalized rows and temporary directories.

## Out Of Scope

- Defining or running the manifest from Plan 1.
- Editing generated normalized rows.
- Changing solver behavior.
- Building manuscript claim text or upgrading abstract/conclusion claims.
</scope>

<threat_model>
## Threat Model

| Threat | Severity | Mitigation |
| --- | --- | --- |
| Builder accepts incomplete row coverage as success | high | Require 15 rows completed or explicitly blocked, grouped as 5 paired groups x 3 variants. |
| Runtime table omits exact infeasibility metadata | high | Required aggregate fields include fallback/status and above-threshold reason. |
| Large greedy gaps are hidden | high | Summary reports gap and overlap and writes claim-narrowing language when thresholds are poor. |
| Diagnostic artifacts become claim-ready | high | Hard-code `claim_ready=false` and include upstream blocker reasons. |
| Source paths are lost | medium | Sidecar metadata stores run dir, run ID, manifest hash, row count, and artifact source path. |
</threat_model>

<action>
Create `Src/computational_tractability.py` with pure helpers to:

1. Load the latest `phase9_exact_greedy_tractability` run from
   `outputs/studies/phase9_exact_greedy_tractability/`.
2. Load `normalized_rows.json`, `study_summary.json`, `manifest_snapshot.yaml`,
   and optional `blockers.json`.
3. Join manifest split metadata onto rows by `split_id`, including
   `solver_scale_variant`, `solver_scale_value`, and `paired_group_id`.
4. Validate:
   - one policy tag: `mainline_optimized_adaptive`;
   - expected scale values: `8`, `12`, `16`;
   - five paired groups, each with all three scale values;
   - 15 rows are completed or explicitly blocked;
   - all completed rows have checkpoint status `loaded`;
   - `checkpoint_path`, `checkpoint_hash`, and `checkpoint_required` are
     present where execution completed;
   - `menu_k == 3` for every row;
   - small exact rows use effective solver `exact`;
   - large rows use effective solver `greedy` or blocked status with
     fallback reason `above_exact_threshold` when completed;
   - `solver_candidate_count` or `max_candidates` is available for reporting.
5. Return a blocked report object rather than raising when rows are explicitly
   blocked by checkpoint, readiness, or execution errors.
</action>
