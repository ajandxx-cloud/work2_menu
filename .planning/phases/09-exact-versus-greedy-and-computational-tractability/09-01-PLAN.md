# Phase 9 Plan 1: Exact-Greedy Study Contract

<objective>
Create the Phase 9 exact-versus-greedy tractability study contract and focused
tests. The manifest must produce the intended 15 solver-scale rows while
preserving paired replay fairness, loaded checkpoint provenance, fixed
`menu_k=3`, and diagnostic `claim_ready=false` status.
</objective>

<scope>
## In Scope

- Add one study manifest:
  `work2_coding/Experiments/studies/phase9_exact_greedy_tractability.yaml`.
- Use known policy tag `mainline_optimized_adaptive` instead of adding new
  policy adapters.
- Encode three solver-scale variants as split metadata and `args_overrides`.
- Add explicit row support for observed `solver_candidate_count` if the current
  normalized row schema does not persist it.
- Add script-style tests for manifest shape, paired fairness, threshold
  fallback contract, checkpoint requirement, row fields, and claim boundary.

## Out Of Scope

- Running the Phase 9 study.
- Building artifact tables, figures, or summaries.
- Rerunning `phase9_dspo_family_validation`.
- Changing passenger choice semantics, pricing semantics, ETA filter behavior,
  or solver algorithms.
- Upgrading claim-ready status.
</scope>

<threat_model>
## Threat Model

| Threat | Severity | Mitigation |
| --- | --- | --- |
| Tractability variants are added as invalid policy tags | high | Use `mainline_optimized_adaptive` and put solver scale in split metadata. |
| Large candidate variants accidentally run exact | high | Tests assert `max_candidates` is greater than `menu_exact_threshold` and exact request falls back to greedy. |
| Candidate count is missing from rows | medium | Persist `solver_candidate_count` from `last_policy_diagnostic` into normalized rows and tests. |
| Paired fairness drifts across variants | high | Tests group by `paired_group_id` and compare seed, data seeds, checkpoint, pricing, HGS, utilities, and `menu_k`. |
| Diagnostic rows are treated as formal claim-ready evidence | high | Manifest and tests require `diagnostic_provisional_blocked` intent and `claim_ready: false`. |
</threat_model>
