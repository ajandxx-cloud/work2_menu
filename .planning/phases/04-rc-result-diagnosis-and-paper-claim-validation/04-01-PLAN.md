# Phase 4 Plan 1: Formal Row And Provenance Diagnostics

<objective>
Produce row-level and paired-difference diagnostics from the selected formal RC
run, with blocker/provenance status visible before any claim interpretation.
The plan creates diagnostic tables only; it does not tune, rerun, or edit
generated formal evidence.
</objective>

<scope>
## In Scope

- Validate the selected completed formal run as the Phase 4 diagnostic input.
- Read formal readiness, artifact status, claim guard, and Phase 3 handoff
  metadata.
- Compute policy-level means, standard deviations, paired split differences,
  direction counts, and uptake-regime summaries.
- Create diagnostic tables under `.planning/results/`.
- Add a small read-only diagnosis helper and script-style test if doing so
  prevents hand-built tables.

## Out Of Scope

- Rerunning formal replay or training checkpoints.
- Tuning manifest parameters based on formal results.
- Editing generated `normalized_rows.json`, CSV rows, artifact tables,
  figures, or claim guard JSON.
- Writing final manuscript claims or changing algorithm/runtime behavior.
</scope>

## Task 2: Add Or Use A Read-Only Diagnosis Helper

**Type:** analysis
**Files:** `work2_coding/scripts/diagnose_rc_formal_claims.py`,
`work2_coding/scripts/test_rc_formal_claim_diagnosis.py`

**Action:**

If no existing helper already produces the required tables, add
`scripts/diagnose_rc_formal_claims.py` with CLI arguments:

```powershell
python scripts/diagnose_rc_formal_claims.py --run-dir outputs/formal_v1/formal_robust_menu/formal_robust_menu-20260614T032323Z-c672286a --readiness-json outputs/phase5_readiness/formal_robust_menu/FORMAL_READINESS.json --artifact-status outputs/phase3_formal_artifacts/ARTIFACT_STATUS.json --claim-guard outputs/phase3_formal_artifacts/manuscript/CLAIM_GUARD.json --output-dir ..\.planning\results
```

The helper should:

1. Load rows using structured JSON/CSV APIs.
2. Validate `5 splits x 7 policies` and completed row metadata.
3. Compute means and population standard deviations for:
   `net_profit`, `operational_cost`, `total_cost`, `acceptance_rate`,
   `served_rate`, `optout_rate`, `home_share`,
   `meeting_point_uptake_rate`, and `service_time_total` where present.
4. Compute paired differences for
   `mainline_optimized_adaptive - baseline` by split and by uptake regime.
5. Include product ablations, fixed/adaptive window ablation, and random/fixed/no
   menu baselines in the paired table.
6. Emit:
   - `.planning/results/RC_FORMAL_POLICY_SUMMARY.csv`
   - `.planning/results/RC_FORMAL_PAIRED_DIFFS.csv`
   - `.planning/results/RC_FORMAL_DIAGNOSTIC_TABLES.md`
7. State that confidence intervals are intentionally omitted because there are
   only five formal splits.

Add a focused script-style test with a temporary mini row set covering:

- paired difference sign and magnitude;
- split/regime grouping;
- blocker propagation from readiness/artifact/claim guard inputs;
- no confidence interval language for a five-split diagnosis.

**Verify:**

