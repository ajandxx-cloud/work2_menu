# Phase 13 Plan 1: Evidence Boundary Audit Deliverables

<objective>
Create the three Phase 13 evidence-boundary deliverables under
`.planning/milestones/claim_ready_resolution/`. The deliverables reconstruct
the current evidence boundary, identify concrete `claim_ready=false` causes,
and classify blockers without repairing gates, running experiments, editing
generated artifacts, or choosing the Phase 16 Path A/B/C decision.
</objective>

<scope>
## In Scope

- Read and summarize planning, paper, result, readiness, frozen-setting, and
  Phase 10 package evidence.
- Compare runtime-source Phase 10 package files with root mirror package files.
- Identify concrete `claim_ready=false` causes from `PACKAGE_STATUS.json`,
  `CLAIM_GUARD.json`, source-family statuses, and prior result summaries.
- Classify causes into the roadmap's nine blocker categories.
- Write:
  - `.planning/milestones/claim_ready_resolution/01_EVIDENCE_BOUNDARY.md`
  - `.planning/milestones/claim_ready_resolution/01_CLAIM_READY_FALSE_CAUSES.md`
  - `.planning/milestones/claim_ready_resolution/01_BLOCKER_TAXONOMY.md`

## Out Of Scope

- Editing generated result rows, generated tables, generated figures, package
  status files, package indexes, or claim guards.
- Regenerating artifacts or manuscript frames.
- Running calibration, final replay, Phase 8/9 replay, or case-study execution.
- Choosing Path A, Path B, or Path C.
- Designing rerun splits, seeds, manifests, or parameters.
- Upgrading manuscript claims by wording.
</scope>

<threat_model>
## Threat Model

| Threat | Severity | Mitigation |
| --- | --- | --- |
| T-13-01: The audit silently resolves conflicts between generated artifacts and planning summaries | high | Require a conflict matrix in `01_EVIDENCE_BOUNDARY.md`; runtime/mirror matches may be merged only when hashes or key fields match. |
| T-13-02: Repeated package blockers become noisy and hide canonical causes | medium | Merge repeated blockers into `CF-*` canonical causes while preserving affected artifact counts and representative ids. |
| T-13-03: Status-supported `C7` is mistaken for empirical claim readiness | high | Require claim-level classification and note that `C7` is status/provenance only. |
| T-13-04: Diagnostic or scaffold sources are repaired by wording | high | Use `do_not_repair_by_wording` and `diagnostic_lock_candidate` labels for insufficient evidence. |
| T-13-05: Phase 13 accidentally authorizes a rerun or Path A/B/C decision | high | Use `recommended_next_action` and downstream owner fields only; prohibit milestone-wide path tendency language. |
| T-13-06: Generated artifacts are modified during the audit | high | Plan writes only `.planning/milestones/claim_ready_resolution/*.md`; verification checks generated artifact roots in git status. |
</threat_model>
