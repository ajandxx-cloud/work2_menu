# Phase 10 Plan 2: Strict Claim Guard And Artifact-Facing Frame

<objective>
Extend the manuscript-frame and package layer so Phase 10 emits a strict
per-claim `CLAIM_GUARD.json`, a source-backed claim checklist, and
artifact-facing frame outputs. The guard must preserve current
`claim_ready=false` status and explicitly block unsupported superiority,
adaptive-window, case-study validation, no-filter recommendation, and
near-optimal greedy claims.
</objective>

<scope>
## In Scope

- Add strict per-claim guard support to `work2_coding/Src/manuscript_claims.py`
  or expose it through `work2_coding/Src/paper_artifacts.py`.
- Generate strict `CLAIM_GUARD.json` in the Phase 10 package output root.
- Generate artifact-facing `claim_checklist.md` and section/source maps.
- Add tests for strict schema, safe/forbidden language, blocked current
  claims, and artifact-only frame depth.

## Out Of Scope

- Replacing the existing general manuscript-frame API in incompatible ways.
- Writing manuscript body sections, abstract text, conclusion text, or polished
  claim prose.
- Upgrading claim-ready status.
- Adding a new claim ladder beyond the Phase 2 design and Phase 4/8/9
  evidence boundaries.
</scope>

<threat_model>
## Threat Model

| Threat | Severity | Mitigation |
| --- | --- | --- |
| T-10-06: Strict guard loses compatibility with existing claim guard tests | high | Add a new strict builder or preserve existing keys while adding `claims`. |
| T-10-07: Unsupported central claim becomes manuscript-allowed | high | Tests assert `C1` is not manuscript allowed while current gates are blocked. |
| T-10-08: Adaptive-window improvement is claimed despite tied rows | high | Claim `C3` must be unsupported/blocked with safe language limited to "not supported in selected rows." |
| T-10-09: Case scaffold becomes external validation | high | Claim `C8` must forbid case-study validation and real passenger behavior language. |
| T-10-10: Phase 9 is presented as near-optimal greedy evidence | high | Claim `C6` must block near-optimal greedy language because fallback/gap evidence is unavailable. |
</threat_model>

**Type:** code
**Files:**

- `work2_coding/Src/paper_artifacts.py`
</read_first>

<action>
Add a strict guard builder with a stable public function, preferably:

```python
build_strict_claim_guard(package_indexes, artifact_statuses=None)
```

The returned JSON-serializable dictionary must include:

- `schema_version: phase10-strict-claim-guard-v1`
- `claim_ready`
- `generated_at_utc`
- `source_package_index`
- `claims`
- `overall_blocker_reasons`

Each item in `claims` must include:

- `claim_id`
- `claim_text`
- `support_status`
- `source_artifacts`
- `blocker_reasons`
- `safe_language`
- `forbidden_language`
- `manuscript_allowed`
- `claim_ready`

Create at least these claim IDs:

- `C1_central_adaptive_menu_superiority`
- `C2_product_ablation_value`
- `C3_adaptive_window_increment`
- `C4_menu_construction_value`
- `C5_eta_robustness_boundary`
- `C6_exact_greedy_computational_credibility`
- `C7_provenance_status_transparency`
- `C8_semi_real_case_validation`

Current support statuses must reflect the actual evidence:

- `C1`: `unsupported_blocked`
- `C2`: `conditional_diagnostic_blocked`
- `C3`: `unsupported`
- `C4`: `conditional_diagnostic_blocked`
- `C5`: `diagnostic_only`
- `C6`: `blocked_diagnostic`
- `C7`: `status_supported`
- `C8`: `scaffold_only_blocked`

Set `manuscript_allowed` true only for status/diagnostic framing where the
safe language is not a positive empirical superiority claim. Under current
source status, overall `claim_ready` must be false.
</action>

<verify>
Run from `work2_coding/`:

```powershell
python - <<'PY'
import sys
sys.path.insert(0, ".")
from Src.paper_artifacts import collect_phase10_sources, build_package_indexes
from Src.manuscript_claims import build_strict_claim_guard
indexes = build_package_indexes(collect_phase10_sources())
guard = build_strict_claim_guard(indexes)
assert guard["schema_version"] == "phase10-strict-claim-guard-v1"
assert guard["claim_ready"] is False
claims = {item["claim_id"]: item for item in guard["claims"]}
assert claims["C1_central_adaptive_menu_superiority"]["manuscript_allowed"] is False
assert claims["C8_semi_real_case_validation"]["support_status"] == "scaffold_only_blocked"
for item in claims.values():
    for field in ["claim_text", "support_status", "source_artifacts", "blocker_reasons", "safe_language", "forbidden_language", "manuscript_allowed", "claim_ready"]:
        assert field in item, (item["claim_id"], field)
print(len(claims))
PY
```
</verify>

- Strict guard function returns all required top-level fields.
- Strict guard contains at least the eight claim IDs listed above.
- Every claim contains all required per-claim fields.
- Overall `claim_ready` is false.
- `C1`, `C3`, `C6`, and `C8` block positive manuscript claims under current
  evidence.
</acceptance_criteria>
