# Phase 7 Plan 2: Planning-Side Validator And Scaffold Closeout

<objective>
Add a planning-side validator for the Phase 7 case-study contract pack, write a
validation summary with `blocking`, `warning`, and `info` findings, and update
planning state to record that Phase 7 created scaffolded contracts only. This
plan closes the phase without running case-study experiments or producing case
evidence.
</objective>

<scope>
## In Scope

- Implement `.planning/data/case_studies/validate_case_contracts.py`.
- Add `.planning/data/case_studies/test_case_contracts.py` with script-style
  assertions for validator behavior.
- Generate `.planning/data/case_studies/VALIDATION_SUMMARY.md`.
- Update the case-study scaffold `README.md` with validator commands.
- Update planning docs to mark `CASE-03` contract coverage and clarify that
  `CASE-05` is not a skip path because Phase 6 approved the case in principle.

## Out Of Scope

- Reading, downloading, validating, or building real external sources.
- Validating OSM/GTFS/OSRM content, road-graph topology, matrix shape,
  reachable pairs, demand rows, or replay outputs.
- Adding runtime validation scripts under `work2_coding/scripts/`.
- Adding runtime study YAML under `work2_coding/Experiments/studies/`.
- Generating normalized rows, artifact tables, figures, or claim-ready
  manuscript text.
</scope>

<threat_model>
## Threat Model

| Threat | Severity | Mitigation |
| --- | --- | --- |
| Validator overreaches into external-data validation | high | Limit checks to planning files, metadata fields, placeholders, labels, and blockers. |
| Validator silently passes a claim-upgrade artifact | high | Treat missing blocker fields or missing prohibitive labels as `blocking`. |
| Runtime study execution is enabled by a placeholder YAML | high | Fail validation if case-study YAML exists under `work2_coding/Experiments/studies/`. |
| Planning closeout implies real passenger evidence | high | Update planning docs with scaffold-only status and simulated-demand/simulated-choice labels. |
</threat_model>

<action>

`--root .planning/data/case_studies` and optional `--write-summary`. The

findings with fields `severity`, `code`, `message`, `evidence_location`,

metadata fields, placeholder/hash field presence, blocker fields set to false,
unlock condition text for provenance/readiness/artifact/claim gates, required
semi-real/simulated labels, seven mainline tags, paired-field vocabulary, route

placeholder language, and absence of `work2_coding/Experiments/studies/case_*`
runtime manifest files.
</action>

</verify>

- The command writes `.planning/data/case_studies/VALIDATION_SUMMARY.md`.
- The summary contains sections for `blocking`, `warning`, and `info`.
