# Phase 8 Plan 1: Must-Have Sensitivity Manifest Contracts

<objective>
Create the executable Phase 8 diagnostic sensitivity manifest suite for the
four must-have dimensions only. The suite preserves `phase8_baseline_validation`
as a prerequisite gate, runs one-factor-at-a-time around frozen/default
settings, and keeps all replay diagnostic/provisional with `claim_ready=false`.
</objective>

<scope>
## In Scope

- Add four study manifests under `work2_coding/Experiments/studies/`:
  `phase8_sensitivity_menu_k`, `phase8_sensitivity_eta_filter`,
  `phase8_sensitivity_uptake_regime`, and `phase8_sensitivity_guardrail`.
- Add one suite manifest under `work2_coding/Experiments/suites/`:
  `phase8_sensitivity_must_have`.
- Use `tier: pilot` and `run_mode: diagnostic` for sensitivity replay.
- Use `mainline_optimized_adaptive` as the sole policy tag in each
  sensitivity study.
- Encode axis metadata in manifest/split metadata so later artifact builders
  can map rows to `sensitivity_axis` and `sensitivity_value`.
- Add script-style tests that validate Phase 8 scope, one-factor discipline,
  diagnostic status, baseline prerequisite, and nice-to-have deferral.

## Out Of Scope

- Running the sensitivity suite.
- Generating normalized rows, tables, figures, or `.planning/results/SENSITIVITY_SUMMARY.md`.
- Running candidate pool, fleet/capacity, pricing-bound, or price-sensitivity
  actual replay.
- Adding no-filter to the main deployable sensitivity comparison.
- Changing algorithm behavior or passenger choice semantics.
</scope>

<threat_model>
## Threat Model

| Threat | Severity | Mitigation |
| --- | --- | --- |
| Sensitivity manifests become a broad calibration grid | high | Require one-factor-at-a-time axis metadata and fixed center settings. |
| Nice-to-have dimensions slip into executable replay | high | Test that no Phase 8 sensitivity manifest varies `max_candidates`, fleet/capacity, or pricing bounds. |
| Diagnostic sensitivity is mistaken for final evidence | high | Use `tier: pilot`, `run_mode: diagnostic`, and explicit claim-ready false metadata. |
| Baseline gate is merged into sensitivity suite | medium | Keep `phase8_baseline_validation` separate and reference it as a prerequisite only. |
</threat_model>
