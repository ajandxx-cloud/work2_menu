# Phase 8 Plan 2: Sensitivity Artifact Builder And Summary Gate

<objective>
Implement generated Phase 8 sensitivity artifact and summary tooling. The
tooling must read normalized rows and manifest snapshots, enforce the baseline
gate and one-factor-at-a-time contract, build diagnostic artifacts, and write
`.planning/results/SENSITIVITY_SUMMARY.md` without upgrading claims.
</objective>

<scope>
## In Scope

- Add `work2_coding/Src/sensitivity_analysis.py` with Phase 8 sensitivity
  loaders, validators, aggregators, and Markdown generation.
- Add CLI wrappers for generated sensitivity artifacts and the planning-side
  sensitivity summary.
- Generate JSON/CSV/LaTeX/figure outputs from normalized rows plus manifest
  snapshots.
- Write `.planning/results/SENSITIVITY_SUMMARY.md` as a conditional boundary
  map with source artifact paths.
- Add script-style tests for baseline blocking, axis validation,
  one-factor-at-a-time discipline, diagnostic status, and summary content.

## Out Of Scope

- Defining or running the manifests from Plan 1.
- Running actual replay.
- Changing passenger choice, routing, menu optimization behavior, or checkpoint
  loading.
- Writing paper-facing result tables by hand.
- Editing abstract/conclusion manuscript language.
</scope>

<threat_model>
## Threat Model

| Threat | Severity | Mitigation |
| --- | --- | --- |
| Builder summarizes rows despite failed baseline gate | high | Load `PHASE8_BASELINE_VALIDATION.json` first and emit blocked summary if not passed. |
| Summary hides failure regimes | high | Report every axis/value/regime status, including failed/blocked rows. |
| Tables are manually authored | high | Generate CSV/LaTeX/figure artifacts directly from rows plus manifest snapshots. |
| Diagnostic results become claims | high | Hard-code `claim_ready=false` and `diagnostic_provisional_blocked` in summary metadata. |
</threat_model>

<action>
Create `Src/sensitivity_analysis.py` with pure helpers to:

1. Load and validate `PHASE8_BASELINE_VALIDATION.json`.
2. Return a blocked sensitivity report when baseline validation is missing,
   malformed, or not `passed`.
3. Discover latest run directories for the four suite members under
   `outputs/studies/`.

   - uptake values are only `low` and `medium`;
   - guardrail axis varies both `service_quit_rate_guardrail` and
     `menu_optout_guardrail`;

   - completed rows have loaded checkpoint status and valid accounting.
