# Phase 8 Plan 3: Gated Diagnostic Replay And Sensitivity Closeout

<objective>
Run Phase 8 diagnostic sensitivity only after the baseline gate passes. Produce
generated diagnostic rows, sensitivity artifacts, and
`.planning/results/SENSITIVITY_SUMMARY.md`, then update planning docs to record
Phase 8 as diagnostic/provisional and not claim-ready.
</objective>

<scope>
## In Scope

- Run the existing `phase8_baseline_validation` actual replay and report.
- Stop with a blocked sensitivity summary if the baseline gate fails.
- If the gate passes, run the `phase8_sensitivity_must_have` suite in actual
  replay mode.
- Build generated sensitivity artifacts and sidecar metadata.
- Generate `.planning/results/SENSITIVITY_SUMMARY.md`.
- Run verification tests and update planning docs for Phase 8 closeout.

## Out Of Scope

- Running final formal replay.
- Running semi-real case experiments.
- Running nice-to-have sensitivity axes.
- Running Phase 9 exact-vs-greedy or DSPO-family validation beyond references
  needed by gates.
- Editing generated rows, generated tables, generated figures, or claim guards
  by hand.
- Upgrading manuscript abstract/conclusion claims.
</scope>

<threat_model>
## Threat Model

| Threat | Severity | Mitigation |
| --- | --- | --- |
| Sensitivity replay runs despite failed baseline gate | high | Branch on `PHASE8_BASELINE_VALIDATION_STATUS`; blocked means write summary and stop. |
| Generated failed rows are hidden | high | Keep failed rows, blockers, and error metadata in summaries and artifacts. |
| Diagnostic artifacts are used as claim-ready | high | Build with diagnostic status and `--allow-incomplete`; summary keeps `claim_ready=false`. |
| Planning docs overclaim | high | Closeout text must say diagnostic/provisional and no manuscript claim upgrade. |
</threat_model>
